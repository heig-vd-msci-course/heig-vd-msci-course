## Évaluation de la semaine

La note de la semaine se compose de deux éléments :

| Élément | Poids |
|---------|-------|
| Projet et présentation | 60 % |
| Évaluation écrite | 40 % |

Chaque élément est noté sur 6 selon la formule :

```text
note = (points obtenus / points maximum) × 5 + 1
```

La note finale est arrondie au dixième.

!!! warning "Règles connues à l'avance"

    Les critères et les contraintes de cette page s'appliquent tels quels. Ils sont publiés dès mardi pour permettre à chaque équipe de s'y préparer.

## Évaluation écrite

### Format

- **Durée** : 60 minutes, de 08h45 à 09h45
- **Sur papier**, sans ordinateur, sans téléphone et sans IA
- **Types de questions** : choix multiples, vrai ou faux, réponses courtes, lecture de code (prédire ce qui s'affiche), recherche de bug, code à compléter

### Matière

Tout ce qui a été vu dans les supports de cours de la semaine, tutoriels compris. En particulier :

**Lundi : algorithmique et programmation visuelle**

- La précision des instructions et les niveaux de langages de programmation
- Les grandes étapes de l'histoire de la programmation
- Les règles du jeu des allumettes, la stratégie gagnante et sa formule
- Les notions d'algorithme, de variable, de condition, de boucle, d'événement et d'opérateur
- L'interface de MakeCode Arcade et les catégories de blocs utilisées

**Mardi : le web**

- Le fonctionnement du web et le rôle de chaque langage (HTML, CSS, JavaScript)
- Les balises HTML vues dans les tutoriels (titres, paragraphes, liens, images)
- Les règles CSS : sélecteur, propriété, valeur, boîtes et espacements
- JavaScript : la console, `let` et `const`, afficher dans la page, réagir à un bouton, `if` et `===`, la boucle `for`
- Les bugs de la journée et la manière de les corriger

**Mercredi : micro:bit et IA**

- Les composants du micro:bit : boutons, matrice LED, capteurs
- Les notions d'entrée, de sortie, de capteur et d'actionneur
- Le contenu de l'après-midi sur l'IA

!!! tip "Se préparer"

    Refaire les tutoriels sans regarder la solution, relire les synthèses de chaque journée et refaire les quiz Wooclap. Le jeudi est le moment idéal pour réviser.

## Projet final

### Choisir une technologie

Chaque équipe choisit **une** des trois technologies de la semaine :

| Technologie | Vue le | Remise |
|-------------|--------|--------|
| **MakeCode Arcade** | Lundi | Lien de partage MakeCode |
| **HTML, CSS et JavaScript** | Mardi | Procédure vue mardi (e-mail, puis lien publié) |
| **micro:bit** | Mercredi | Lien de partage MakeCode et démonstration sur la carte |

### Choisir une option

**Option A : améliorer le jeu des allumettes**

L'équipe ajoute **une amélioration par membre** à sa version du jeu. Chaque amélioration a une personne responsable, capable de l'expliquer.

Exemples d'améliorations :

- L'ordinateur joue contre la joueuse en appliquant la stratégie gagnante
- Choisir le nombre d'allumettes au début de la partie
- Compter les points sur plusieurs manches
- Afficher un écran de victoire ou de défaite
- Ajouter des sons ou une musique qui réagissent au jeu
- Animer le retrait des allumettes
- Indiquer à qui c'est le tour de jouer
- Empêcher les coups interdits (retirer plus d'allumettes qu'il n'en reste)

**Option B : projet libre**

L'équipe crée un nouveau projet sur un sujet de son choix. Il comporte une base qui fonctionne, plus **une fonctionnalité par membre**. Le projet doit être validé par l'équipe enseignante à partir des objectifs notés dans la feuille des équipes.

### Exigences communes

Quelle que soit l'option, le projet utilise au minimum :

- une **variable**
- une **condition**
- une **boucle**
- un **événement**

L'équipe doit pouvoir montrer où chacune de ces notions se trouve dans son code.

| Taille de l'équipe | Améliorations ou fonctionnalités attendues |
|--------------------|--------------------------------------------|
| 4 personnes | 4 |
| 3 personnes | 3 |
| 2 personnes | 2 |
| 1 personne | 1 |

## Critères d'évaluation

Chaque critère est évalué sur 2 points :

| Points | Signification |
|--------|---------------|
| 0 | Le critère n'est pas respecté : l'élément est absent, hors sujet ou montre une compréhension très limitée |
| 1 | Le critère est partiellement respecté : des éléments essentiels manquent, sont imprécis ou incorrects |
| 2 | Le critère est pleinement respecté : tout ce qui est attendu est présent, précis et maîtrisé |

| # | Critère | Points |
|---|---------|--------|
| 1 | La démonstration en direct fonctionne | 2 |
| 2 | Le projet est publié et accessible via son lien | 2 |
| 3 | Une variable, une condition, une boucle et un événement sont présents et montrés dans le code | 2 |
| 4 | Le nombre d'améliorations ou de fonctionnalités correspond au nombre de membres | 2 |
| 5 | L'identité créative de l'équipe est visible dans le projet | 2 |
| 6 | Les délais sont respectés (feuille des équipes mercredi, remise vendredi) | 2 |
| 7 | Les difficultés rencontrées et les solutions trouvées sont expliquées | 2 |
| 8 | L'élocution est claire et le fil conducteur de la présentation est logique | 2 |
| 9 | Le temps imparti est respecté | 2 |
| 10 | Les réponses aux questions de l'équipe enseignante sont correctes, y compris sur le code des améliorations | 2 |
| 11 | Toute l'équipe participe activement (parole, slides ou démonstration) | 2 |
| 12 | Le comportement de l'équipe est fairplay et respectueux (global sur la semaine) | 2 |
| | **Total** | **24** |

## Contraintes

Les contraintes ne rapportent pas de points. Elles doivent toutes être respectées. Les sanctions s'appliquent à **toute l'équipe**.

| Contrainte | En cas de non-respect |
|------------|-----------------------|
| Le projet indique qu'il a été réalisé dans le cadre du cours MSCI à la HEIG-VD | Critère concerné à 0 |
| Les améliorations ne sont pas seulement cosmétiques : changer des couleurs, une police ou une image compte au maximum pour une seule amélioration | Amélioration non comptée |
| L'usage de l'IA est déclaré (quand, comment, pourquoi) et l'équipe sait expliquer le code produit | Note du projet à 1 |
| La musique, les images et les sons sont libres de droits ou leur source est citée | Critère concerné à 0 |
| Le contenu peut être présenté publiquement au nom de la HEIG-VD : aucun contenu discriminatoire, haineux, sexuel ou violent gratuit, aucune moquerie visant une personne réelle | Note du projet à 1 |
| Toutes les personnes sont présentes pendant les présentations des autres équipes | Note du projet à 1 |
| Le silence et le respect sont de mise pendant les présentations | 1 point retiré de la note du projet |
| Il est formellement interdit de filmer, photographier ou enregistrer qui que ce soit à son insu | Note du projet à 1 |

!!! note "Pourquoi ces contraintes ?"

    Les projets sont publiés en ligne sous le nom de l'école et présentés devant toute la classe. Ces règles sont celles de toute publication publique et de toute présentation professionnelle.

!!! tip "Vidéo de son propre projet"

    Une capture d'écran ou une vidéo de son projet dans les slides est autorisée, tant qu'aucune personne n'y apparaît.
