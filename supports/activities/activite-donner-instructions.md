# Donner des instructions

## Apercu

| Duree | Format | Materiel |
|-------|--------|----------|
| 45 min | Binomes | Voir preparation selon option |

## Objectifs pedagogiques

- Comprendre qu'un ordinateur execute exactement ce qu'on lui dit
- Experimenter la difficulte de donner des instructions precises
- Decouvrir l'importance d'un vocabulaire limite et structure
- Faire le lien entre instructions humaines et code informatique

## Concept cle

> Un ordinateur est comme ton ou ta partenaire dans cette activite : il execute EXACTEMENT ce que tu lui dis, rien de plus, rien de moins. Il ne devine pas, il n'interprete pas, il ne pose pas de questions.

---

## Trois options au choix

L'enseignante choisit UNE option selon le materiel disponible et l'espace.

---

## Option A - Labyrinthe

### Description
Une personne ferme les yeux (ou tourne le dos). Sa ou son partenaire la guide a travers un parcours simple dans la salle en utilisant uniquement des commandes predefinies.

### Materiel necessaire
- [ ] Espace degage dans la salle (ou couloir)
- [ ] Obstacles simples : chaises, sacs, cones (optionnel)
- [ ] Bandeaux pour les yeux (optionnel, plus immersif)
- [ ] Chronometre ou telephone

### Vocabulaire autorise (a afficher)

| Commande | Signification |
|----------|---------------|
| `AVANCE X` | Fait X pas en avant (X = 1, 2, 3...) |
| `RECULE X` | Fait X pas en arriere |
| `TOURNE GAUCHE` | Pivote de 90 degres a gauche |
| `TOURNE DROITE` | Pivote de 90 degres a droite |
| `STOP` | Arrete-toi immediatement |
| `DEMI-TOUR` | Pivote de 180 degres |

**Interdit** : "un peu", "la-bas", "attention", "non pas comme ca", "vers la fenetre", etc.

### Mise en place du parcours
- Definir un point de depart et un point d'arrivee
- Placer 2-3 obstacles simples entre les deux
- Le parcours doit etre realisable en 8-10 commandes maximum

## Option B - Dessin aveugle

### Description
Une personne a un dessin simple devant elle. Elle doit le decrire pour que sa ou son partenaire le reproduise sans voir l'original. Aucune question n'est autorisee.

### Materiel necessaire
- [ ] Dessins modeles imprimes (voir annexe ou creer les votres)
- [ ] Feuilles blanches A4 (une par tentative)
- [ ] Crayons ou feutres
- [ ] Separation visuelle (dos a dos, ou carton entre les deux)
- [ ] Chronometre

### Vocabulaire autorise (a afficher)

| Commande | Signification |
|----------|---------------|
| `TRACE UNE LIGNE` | Du point actuel, trace une ligne |
| `DE X A Y` | Depuis position X vers position Y |
| `HAUT / BAS / GAUCHE / DROITE` | Direction |
| `PETIT / MOYEN / GRAND` | Taille relative |
| `CERCLE` | Forme ronde |
| `CARRE` | Forme carree |
| `TRIANGLE` | Forme triangulaire |
| `AU CENTRE` | Au milieu de la feuille |
| `EN HAUT / EN BAS` | Position verticale |
| `A GAUCHE / A DROITE` | Position horizontale |
| `DANS` | A l'interieur d'une forme |
| `A COTE` | Adjacent a |
| `AU-DESSUS / EN-DESSOUS` | Position relative |

**Interdit** : "tu vois ?", "c'est comme...", "non refais", montrer avec les mains, etc.

### Dessins suggeres (difficulte croissante)
1. **Facile** : Soleil (cercle + traits), maison simple, coeur
2. **Moyen** : Etoile a 5 branches, bonhomme, arbre
3. **Difficile** : Emoji clignant de l'oeil, voiture, fusee

## Option C - Construction

### Description
Une personne a une construction simple (Lego, Kapla, ou blocs). Elle doit guider sa ou son partenaire pour reproduire la meme construction avec des pieces identiques, sans montrer l'original.

### Materiel necessaire
- [ ] Jeu de construction : Lego Duplo, Kapla, blocs en bois, ou meme livres/objets
- [ ] Deux jeux de pieces identiques par binome
- [ ] Separation visuelle (carton, dos a dos)
- [ ] Modeles pre-construits (ou laisser un partenaire construire d'abord)
- [ ] Chronometre

### Vocabulaire autorise (a afficher)

| Commande | Signification |
|----------|---------------|
| `PRENDS` | Selectionne une piece |
| `PIECE ROUGE / BLEUE / etc.` | Couleur de la piece |
| `GRANDE / PETITE / MOYENNE` | Taille de la piece |
| `POSE` | Place la piece |
| `SUR` | Au-dessus, en contact |
| `A COTE` | Adjacent horizontalement |
| `DEVANT / DERRIERE` | Position avant/arriere |
| `A GAUCHE / A DROITE` | Position laterale |
| `TOURNE` | Pivote la piece |
| `HORIZONTAL / VERTICAL` | Orientation de la piece |
| `ALIGNE` | Sur la meme ligne que |

**Interdit** : "l'autre piece", "celle-la", montrer, regarder la construction de l'autre

### Constructions suggerees
- Tour simple (3-4 pieces empilees)
- Escalier (3 marches)
- Pont (deux piliers + une piece dessus)
- Lettre L ou T

## Deroulement detaille

### Phase 1 - Introduction (5 min)

**Ce que dit l'enseignante :**

> "Aujourd'hui, on va faire une experience. Vous allez decouvrir a quel point c'est difficile de donner des instructions precises. Et spoiler : c'est exactement ce qu'on fait quand on programme !"

1. Expliquer brievement l'activite choisie (2 min)
2. Former les binomes (1 min)
3. Presenter les regles strictes (2 min) :
   - L'executrice ou executeur ne peut PAS poser de questions
   - L'instructrice ou instructeur ne peut utiliser QUE le vocabulaire affiche
   - Pas de gestes, pas de "oui/non", pas de corrections du genre "non, pas ca"

### Phase 2 - Premier essai (8 min)

| Temps | Action |
|-------|--------|
| 0-1 min | Distribution du materiel, mise en place |
| 1-5 min | Premier essai (4 min chrono) |
| 5-6 min | Revelation et comparaison |
| 6-8 min | Discussion rapide en binome : "Qu'est-ce qui a ete difficile ?" |

**Conseils pour l'enseignante :**
- Circuler et observer sans intervenir
- Noter les erreurs interessantes pour le debrief
- Rappeler gentiment les regles si quelqu'un triche

### Phase 3 - Echange de roles (8 min)

| Temps | Action |
|-------|--------|
| 0-1 min | Changement de roles, nouveau materiel si besoin |
| 1-5 min | Deuxieme essai (4 min chrono) |
| 5-6 min | Revelation et comparaison |
| 6-8 min | Discussion en binome : "C'etait plus facile d'etre instructeur ou executeur ?" |

### Phase 4 - Deuxieme round avec amelioration (10 min)

**Ce que dit l'enseignante :**

> "Maintenant que vous avez compris les difficultes, on refait un tour. Cette fois, essayez d'appliquer ce que vous avez appris."

| Temps | Action |
|-------|--------|
| 0-4 min | Troisieme essai (nouveau defi, memes roles qu'au debut) |
| 4-5 min | Revelation |
| 5-9 min | Quatrieme essai (roles inverses) |
| 9-10 min | Revelation finale |

### Phase 5 - Debrief collectif (12 min)

#### Questions de debrief (a poser au groupe)

1. **Sur l'experience**
   - "Qu'est-ce qui a ete le plus frustrant ?"
   - "Levez la main si votre partenaire a fait exactement ce que vous pensiez avoir dit."
   - "Qu'est-ce qui s'est ameliore au deuxieme tour ?"

2. **Sur la precision**
   - "Donnez un exemple d'instruction qui a ete mal comprise."
   - "Comment auriez-vous pu la formuler autrement ?"
   - "Pourquoi le vocabulaire limite aide-t-il finalement ?"

3. **Connexion avec la programmation**

**Ce que dit l'enseignante :**

> "Ce que vous venez de vivre, c'est exactement ce qui se passe quand on programme :
>
> - Votre partenaire etait l'ordinateur : il fait ce que vous dites, pas ce que vous pensez
> - Le vocabulaire limite, c'est le langage de programmation : on ne peut pas tout dire n'importe comment
> - Les erreurs ne sont pas des echecs : ce sont des bugs qu'on corrige
> - Le deuxieme essai etait meilleur : c'est l'iteration, on ameliore son code petit a petit"

#### Points cles a faire emerger

| Constat de l'activite | Equivalent en programmation |
|-----------------------|----------------------------|
| "Mon partenaire n'a pas compris" | Un bug n'est pas une erreur de l'ordinateur, c'est une erreur d'instruction |
| "Je ne pouvais pas dire 'la-bas'" | Un langage a une syntaxe precise, on ne peut pas inventer |
| "C'etait frustrant de ne pas pouvoir poser de questions" | Le code ne pose pas de questions, il execute |
| "Au 2e essai, c'etait plus clair" | On itere, on teste, on ameliore |
| "Il fallait decomposer chaque action" | Un programme est une suite de petites instructions |

### Phase 6 - Cloture (2 min)

**Ce que dit l'enseignante :**

> "Gardez cette experience en tete pour toute la semaine. Chaque fois que votre code ne marche pas, demandez-vous : est-ce que j'ai ete assez precis ? Est-ce que l'ordinateur a fait ce que j'ai dit... ou ce que je pensais ?"

## Variantes et adaptations

### Pour un groupe plus grand (+ de 30 personnes)
- Former des groupes de 3 : un instructeur, un executeur, un observateur (qui note les erreurs)
- Les observateurs donnent un feedback structure apres chaque essai
- Rotation des roles a chaque essai

### Pour un groupe plus petit (- de 12 personnes)
- Un seul binome fait la demonstration devant tout le monde pour le premier essai
- Debrief plus approfondi avec chaque binome qui partage
- Possibilite de faire les 2 ou 3 options successivement

### Version competition amicale
- Chronometrer chaque binome
- Compter le nombre d'instructions utilisees
- Prime a la precision ET a la rapidite
- Attention : peut augmenter le stress, a utiliser si le groupe est a l'aise

### Version numerique (si salle informatique)
- Utiliser un outil de dessin collaboratif (Excalidraw, Figma)
- Un partenaire dicte par chat uniquement (pas de vocal)
- Simule encore mieux la "communication" avec un ordinateur

### Pour raccourcir (30 min)
- Supprimer le deuxieme round (Phase 4)
- Reduire le debrief a 8 min
- Garder uniquement les questions essentielles

### Pour allonger (60 min)
- Ajouter une phase de "creation de vocabulaire" : les binomes peuvent proposer 2-3 nouvelles commandes
- Faire un essai supplementaire avec ce vocabulaire enrichi
- Reflexion : "Pourquoi les langages evoluent-ils ?"

## Checklist enseignante

### Avant l'activite
- [ ] Choisir l'option (A, B ou C)
- [ ] Preparer le materiel necessaire
- [ ] Afficher ou projeter le vocabulaire autorise
- [ ] Preparer l'espace (degager si labyrinthe, tables en binomes sinon)
- [ ] Avoir un chronometre visible

### Pendant l'activite
- [ ] Rappeler les regles strictement au debut
- [ ] Circuler et observer sans corriger
- [ ] Noter les "bugs" interessants pour le debrief
- [ ] Respecter le timing de chaque phase
- [ ] Encourager sans valider ("interessant !" plutot que "c'est bien")

### Apres l'activite
- [ ] Faire le lien explicite avec la programmation
- [ ] S'assurer que le message cle est compris
- [ ] Recuperer les dessins ou photos des constructions (optionnel, pour memoire)

```
REGLES DU JEU

1. L'executeur ne pose AUCUNE question
2. L'instructeur utilise UNIQUEMENT le vocabulaire affiche
3. Pas de gestes, pas de "oui/non"
4. 4 minutes par essai
5. Ensuite, on inverse les roles !

UN ORDINATEUR = TON PARTENAIRE
Il fait ce que tu DIS, pas ce que tu PENSES.
```
